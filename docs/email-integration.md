# Спецификация интеграции почты (Beget + расширяемый контракт)

Документ фиксирует текущую интеграцию с Beget и общий контракт обработки почтовых событий для workspace.

## 1) Параметры подключения Beget

### Исходящая почта (SMTP)

- Сервер: `smtp.beget.com`
- Порт `2525` — `STARTTLS` (или без шифрования, **не рекомендуется**)
- Порт `465` — `SSL/TLS`
- Аутентификация: логин/пароль (обычный пароль)

### Входящая почта (POP3/IMAP)

- POP3 сервер: `pop3.beget.com`
  - Порт `110` — `STARTTLS`
  - Порт `995` — `SSL/TLS`
- IMAP сервер: `imap.beget.com`
  - Порт `143` — `STARTTLS`
  - Порт `993` — `SSL/TLS`
- Аутентификация: логин/пароль (обычный пароль)

## 2) Рекомендованный режим для продукта

Для командного workspace лучше использовать **IMAP (`imap.beget.com`)**, потому что письма остаются на сервере и доступны для синхронизации несколькими клиентами/сервисами.

Рекомендуемые значения по умолчанию:

- `incoming_protocol = imap`
- `incoming_host = imap.beget.com`
- `incoming_port = 993`
- `incoming_security = ssl`
- `outgoing_host = smtp.beget.com`
- `outgoing_port = 465`
- `outgoing_security = ssl`

## 3) Минимальный внутренний контракт события

```json
{
  "eventId": "uuid",
  "provider": "beget",
  "accountId": "string",
  "messageId": "string",
  "threadId": "string",
  "receivedAt": "ISO-8601",
  "from": [{ "name": "", "email": "" }],
  "to": [{ "name": "", "email": "" }],
  "subject": "string",
  "preview": "string",
  "hasAttachments": true,
  "labels": ["INBOX"]
}
```

## 4) Бизнес-правила маршрутизации

- Если тема содержит `[#task]` → создать задачу в выбранном проекте.
- Если письмо содержит дату/время и `[#meeting]` → предложить событие календаря.
- Если отправитель VIP/клиентский домен → уведомление высокого приоритета.

## 5) Безопасность

- Хранить пароль почты в зашифрованном виде (как минимум через managed secrets).
- Не использовать незащищённые порты в production.
- Ограничить доступ к mailbox-конфигам через RLS и сервисные роли.
- Вести журнал синхронизаций и ошибок для аудита.
